## 核心論點

- 架構是「受限」與「自由」之間的平衡:接受約束,換取基礎設施替你解決一類問題。
- 架構的假設有有效期。與需求吻合時是便利,假設改變時抽象開始洩漏,架構變成阻力。
- Agent harness 的設計:Everything is a plugin,加上 Session = list[Event]。難點不在解耦,在協同。

## 1. 150 行的 agent 為什麼不夠

> 📷 圖:最小 Agent Loop 被真實世界的需求包圍:恢復、暫停與改需求、權限、預算、驗收、同步(見 [slides9](https://jyywiki.cn/GSE/2026/slides9.html) 第 7 張)

- 最小 loop 能跑,但它假設網路與服務不會中斷。這是來自需求的 essential complexity。
- API 中斷要先分清情況:暫時性故障可以有限重試;輸入損壞或權限不足,原樣重試沒用;沒收到結果不等於沒有執行。
- 恢復後先核實實際狀態,不能直接重放有副作用的操作。可靠性包含「不多做一次」。

## 2. 架構的交換:給出什麼、得到什麼、何時失效

| 架構 | 接受的約束 | 換到的便利 | 假設被打破時 |
| --- | --- | --- | --- |
| 作業系統行程 | 只在自己的位址空間執行,經系統呼叫申請資源 | 隔離,像擁有自己的機器 | 記憶體不夠:頻繁換頁、被 OOM 殺掉 |
| 托管語言(Java) | 物件佈局與回收時機交給執行期 | 專注業務,不用手動 free | 要即時回應時,GC 暫停進入使用者可感知的延遲 |
| LAMP | 一次操作 = 請求 → 處理 → 讀寫資料庫 → 回頁面 | 單庫交易、現成的 Web 與持久化設施 | 即時協作佔住工作行程;外部支付無法靠資料庫回滾撤銷 |
| Event Sourcing | 不能覆寫狀態,變更只能以事件表達 | 審計、重建、查詢過去狀態 | 回放不能再扣一次款;歷史匯率要存當時的輸入 |
| MapReduce | 計算要寫成 map → 分組 → reduce | 自動並行、調度、失敗重試 | 熱門 key 傾斜;重試會重複執行副作用 |

- 共同教訓:被隱藏的成本(物理資源、延遲、副作用)在假設失效時會回到開發者面前。
- 演進也是這樣來的:批處理不夠靈活才有 Spark(DAG、快取),等不了資料到齊才有 Flink(持續處理、水位線),各自又帶來新的約束。
- 社會層面:工廠通電後沿用舊廠房佈局也能用,但重組設備與流程才兌現收益。AI 讓實作變便宜之後,瓶頸可能移向驗收、信任與物理執行。

## 3. DeepSeek Harness 的設計

> 📷 圖:插件掛在總線上:業務插件、Agent / Loop、Session、投影、UI 插件之間的少量協作介面(見 [slides9](https://jyywiki.cn/GSE/2026/slides9.html) 第 25 張)

- **Everything is a plugin**:每個插件有私有狀態,彼此不必知道對方的實作,生命週期交給框架管(類比作業系統管行程)。
- **Session = list[Event]**:只追加已提交的事實。模型的訊息歷史、業務狀態都是同一個 Session 的投影,這就是 Event Sourcing。
- 少量協作介面:

| 介面 | 用途 |
| --- | --- |
| `session.append` / `session/event` | 記錄自己負責的事件;觀察已提交的事實 |
| 投影(`deriveMessages`、`sessionProjections`) | 從事實生成模型訊息歷史與業務狀態 |
| `followup` / `inject` / `steer` | 向 agent 送輸入:開新一輪、補充上下文但不喚醒、盡快介入 |
| `systemPrompt.context` | 持續貢獻隨狀態變動的上下文 |
| `agent/pre-step` hook | 在執行前改寫待執行的決策 |

- 關鍵區分:已發生的事實只能觀察,要更正就追加新事件;尚未執行的決策才可以被 hook 改寫。
- 有了這套介面,agent 可以自己熱插拔插件(Creator Mode)。

## 4. 代價與方向

- 代價是生態碎片,插件間的語義衝突得自己管:A 改寫輸入、B 檢查輸入,順序改變結果;兩個 hook 一個要繼續、一個要停。
- 每個插件單獨合理,不保證組合起來合理:十個各壓縮一半的上下文壓縮插件,疊起來只剩 1/1024。
- 好處:介面簡單,把依賴具體需求的設計交給使用者,試錯留在使用者現場(von Hippel 的用戶創新工具包)。
- 兩個方向:
  - 大型 App 的 AI 增強:現有應用只要接一層很薄的抽象(鎖定物件、序列化物件、UI),模型就能依意圖臨時組合既有能力。
  - GenUI:模型輸出 HTML + JS 卡片,卡片再把資訊注入上下文,形成雙向通道。點擊表達精確動作,自然語言表達意圖。
